# Codenotch + ccauth: um anel por conta e troca de conta pelo notch

Fork local do Codenotch (upstream `vinzdg/codenotch`, base `6522e9f`), branch `ccauth`.
O dono tem várias contas Claude e OpenCode Go geridas pela CLI `ccauth`. O notch passa a
mostrar um anel por conta (lido de `ccauth status --json`) e o menu de clique direito
ganha "Alternar <família> para <alias>…", que roda `ccauth <família> switch <alias>`.

Regra de convivência com o upstream: código novo em arquivos novos
(`Sources/Providers/Ccauth/`, `Tests/Ccauth*Tests.swift`); nos arquivos existentes,
só ganchos curtos. Comentários em PT-BR; nomes no código em inglês, no estilo do repo.

## Contrato do ccauth (schema 2)

Amostra real, sem dados pessoais: `docs/plans/ccauth-status-sample.json`.

- `ccauth status --json --max-age 60 --lock-wait 30` → ~1,2 s. `--no-usage` → ~0,7 s
  (contas sem cota; serve para descobrir as contas ao abrir o app).
- Topo: `schema` (2), `ok`, `generated_at`, `warnings`, `claude{ok, active, accounts[]}`,
  `opencode{ok, available, unavailable_reason, active, accounts[]}`.
- Conta Claude: `alias`, `email`, `active`, `in_use`, `login_expires_at`,
  `quota{session, week, fable: {used_percent, resets_at}|null, fetched_at, stale, stale_reason}`.
- Conta OpenCode: `alias`, `credential_id`, `kind` (`oauth`|`key`), `email`, `workspace`,
  `active`, `key_invalid`, `quota{rolling, weekly, monthly: {used_percent, resets_at, exhausted}|null,
  fetched_at, stale, stale_reason}`.
- Datas ISO 8601 com `Z`, às vezes `null`. `used_percent` é 0–100.
- `quota` pode faltar inteira com `--no-usage`. Decodifique tudo como opcional, exceto `alias`.
- Troca: `ccauth claude switch <alias> --json --lock-wait 30` e
  `ccauth opencode switch <alias> --json --lock-wait 30`. Stdout: um JSON com `ok: true|false`
  e, na falha, `error` (string). Pode levar até ~60 s (login/refresh); espere até 120 s.
- O app de interface não herda o PATH do shell. Rode o binário com ambiente montado:
  `PATH=/opt/homebrew/bin:$HOME/.local/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin`,
  mais `HOME`, `USER` e `LOGNAME` do processo (sem USER/LOGNAME o `claude` filho diz
  "Not logged in"). Localize o binário procurando `ccauth` nessas pastas, nessa ordem.
- Referência que já funciona (TypeScript, fork Raycast):
  `/Users/gustavo/Desktop/Gustavo/Referência/Software e Ferramentas/agent-usage-ccauth/src/ccauth/`
  — `client.ts` (PATH, timeout, leitura do `ok`/`error`), `switch.tsx` e `switch-text.ts`
  (texto do alerta de confirmação e do resultado).

## Mapeamento para o modelo do Codenotch

- Um provider por conta. id `ccauth-claude-<slug>` / `ccauth-opencode-<slug>`
  (slug = alias minúsculo, não-alfanumérico → `-`). displayName = alias.
  glyph `.claude` / `.opencode`. `fidelity: .official`.
- Janelas Claude (mesmos ids e rótulos do provider nativo, `ClaudeOAuthProvider.swift:910-930`):
  `session` → id `session`, `L10n.t("Current session")`, duração 5 h;
  `week` → id `weekly_all`, `L10n.t("All models")`, 7 dias;
  `fable` → id `weekly_fable`, rótulo `"Fable"`, 7 dias.
  `headlineID: "session"`, `weeklyID: "weekly_all"`.
- Janelas OpenCode (mesmos do `OpenCodeUsage.swift:30-40`): `rolling` (`L10n.t("5h limit")`, 5 h),
  `weekly` (`L10n.t("Weekly limit")`, 7 dias), `monthly` (`L10n.t("Monthly limit")`, duração nil).
  `headlineID: "rolling"`, `weeklyID: "weekly"`, `plan: "Go"`.
- Janela `null` ou sem `used_percent` → omitida. `usedFraction = used_percent / 100`.
- `quota.stale == true` com `fetched_at` → `status: .stale(since: fetched_at)`; sem `fetched_at`
  e sem janela → lance `UsageProviderError.badResponse(status: 0)`… exceto `key_invalid == true`,
  que lança `UsageProviderError.needsAuth`.
- Conta ativa: `plan` recebe `"Ativa"` (Claude) / `"Go · Ativa"` (OpenCode); a inativa,
  nil / `"Go"`. É o texto do tooltip; não use só cor (o dono é daltônico).
- `account()` devolve `ProviderAccount(label: email, plan: <o mesmo acima>, source: "ccauth", manageURL: nil)`.
- `signInRoute`: `.command("ccauth claude login", name: "ccauth")` / `.command("ccauth opencode switch", name: "ccauth")`.
- `skipsIdleRefresh` fica no padrão (false): a leitura é barata e coalescida.

### Task 1 — identidade do fork, cliente e providers (arquivos novos + 2 ganchos)

1. `project.yml`: `PRODUCT_BUNDLE_IDENTIFIER` → `im.gustavo.codenotch-ccauth` (testes:
   `im.gustavo.codenotch-ccauth.tests`); `SUEnableAutomaticChecks: false`. Comentário curto
   dizendo por quê (o Sparkle trocaria o fork pelo app oficial).
2. `Sources/App/Updater.swift`: `start()` e a verificação manual não fazem nada quando
   `Bundle.main.bundleIdentifier != "com.vinz.codenotch"` (guard no início, com comentário).
   Leia o arquivo inteiro e cubra todo caminho que dispara uma verificação.
3. `Sources/Providers/Ccauth/CcauthStatus.swift`: structs `Decodable` do schema 2 (acima)
   e as funções puras de mapeamento conta → `[LimitWindow]`, `ProviderStatus`, `plan`.
4. `Sources/Providers/Ccauth/CcauthClient.swift`: classe/actor compartilhado (`static let shared`).
   - `runner` injetável (protocolo ou closure `(args) async throws -> (stdout: Data, exit: Int32)`),
     com a implementação real em `Process` (ambiente da seção acima, timeout com `terminate()`).
   - `status() async throws -> CcauthStatus`: coalesce — chamadas concorrentes esperam a mesma
     execução; resultado reaproveitado por 20 s. `invalidate()` zera o cache.
   - `lastStatus` legível de forma síncrona (lock), para o menu montar os itens sem `await`.
   - `discoverAccountsSync() -> CcauthStatus?`: roda `status --json --no-usage --lock-wait 10`
     de forma síncrona (abertura do app); nil se o binário não existe, falha ou `schema != 2`.
   - `switchAccount(family:alias:) async -> Result<Void, CcauthError>`: `<família> switch <alias>
     --json --lock-wait 30`, timeout 120 s; lê `ok`/`error` do JSON; chama `invalidate()` no fim.
5. `Sources/Providers/Ccauth/CcauthAccountProvider.swift`: `UsageProvider` por conta
   (família + alias + email), lendo `CcauthClient.shared.status()` e mapeando pela função pura.
   Conta que sumiu do status → `UsageProviderError.needsAuth`.
6. Testes `Tests/CcauthStatusTests.swift` e `Tests/CcauthClientTests.swift`, com a amostra
   embutida como string literal: decodificação; janelas e rótulos das 5 contas; Allan → stale;
   "API key" → needsAuth; Default → mensal 1,0; ativo → plan; coalescência (2 chamadas
   concorrentes = 1 execução do runner); cache de 20 s e `invalidate()`; switch com `ok:false`
   devolve o `error`; schema 3 → erro.
